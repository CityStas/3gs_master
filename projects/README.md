# projects/ - где живут проекты

Одна раскладка, один движок на папку:

```
projects/
  three/<name>/     engine=threejs   (папка называется `three`, движок - `threejs`)
  godot/<name>/     engine=godot
  unity/<name>/     engine=unity
  roblox/<name>/    engine=roblox
```

`<name>/engine.json` **не обязателен**: движок наследуется от `projects/<engine>/engine.json`.
Именно поэтому эти четыре файла лежат в git, а сами проекты - нет. Маркер на папке
движка - инициализатор: он определяет, какой профиль агента (`pi-home-three`,
`pi-home-godot`, …), какой системный промпт, какие скиллы и какой набор MCP-серверов
получит сессия. Папка без маркера и без маркера у родителя попадает в дефолт
`threejs` - то есть проект на Godot получил бы Three.js-инструменты и молчание в лог.

Раскладку читает **один** модуль - [`project_layout.py`](../project_layout.py);
`projects/README.md` - документация, а не второй источник правды.

## Создать проект

```cmd
dev.cmd my_game          :: папка projects/three/my_game (движок по умолчанию)
studio.cmd my_game       :: то же + студия
```

Лаунчер создаёт папку и пишет `data/active_project.txt`. Внутри может быть пусто -
файлы создаёт агент.

Проект другого движка: положить папку в `projects/godot/` (или `unity/`, `roblox/`) -
маркер родителя сработает сам. Свой `engine.json` внутри проекта нужен, только если
проект лежит не в своей папке; значение обязано быть одним из `threejs`, `godot`,
`unity`, `roblox` - иначе `tools/project_context.py` вернёт ошибку, а не догадку.

## Что здесь НЕ лежит

Содержимое проектов не версионируется: `projects/*` закрыт в `.gitignore`, открыты
только четыре `engine.json` и этот файл. Проверить, что видит git:

```cmd
git ls-files projects
```

Должно быть ровно пять строк. Если появилась шестая - в `.gitignore` сломали
`!projects/<engine>/engine.json` (типичная причина: правило `projects/` вместо
`projects/*`, при котором git вообще не заходит внутрь каталога).
