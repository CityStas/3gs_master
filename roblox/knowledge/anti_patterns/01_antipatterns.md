# Anti-patterns: что выглядит рабочим, но ломается

## 1. Клиент решает, сколько стоит предмет

```lua
-- ПЛОХО
buyButton.Activated:Connect(function()
    Remotes.Purchase:FireServer("sword", 100)   -- цена пришла с клиента
end)
```

```lua
-- ХОРОШО: сервер знает цену
Remotes.Purchase:FireServer("sword")
```

Клиент — недоверенная среда. Любое число, влияющее на экономику, берётся из серверной
таблицы.

## 2. `RemoteFunction:InvokeClient` с сервера

Серверный поток ждёт ответа клиента. Клиент может не ответить никогда (вышел, завис,
эксплойт) — поток висит навсегда. Вместо этого: два `RemoteEvent` (запрос и ответ) или
данные, которые сервер и так знает.

## 3. `while true do` без yield

```lua
-- ПЛОХО: поток никогда не отдаёт управление, игра висит
while true do
    if player.Character then update() end
end
```

```lua
-- ХОРОШО: событие вместо опроса
RunService.Heartbeat:Connect(update)
```

## 4. `Instance.new("Part", parent)`

Второй аргумент устарел: объект появляется в дереве до настройки свойств, и каждое
последующее изменение реплицируется отдельно.

```lua
local part = Instance.new("Part")
part.Size = Vector3.new(4, 1, 4)
part.Anchored = true
part.Parent = workspace            -- Parent последним
```

## 5. Секреты и серверная логика в `ReplicatedStorage`

`ReplicatedStorage` реплицируется всем клиентам. Всё, что там лежит, читается
эксплойтом: ключи API, конфиги с ценами «на будущее», серверные модули. Серверные
модули — в `ServerStorage`.

## 6. `wait()` / `spawn()` / `delay()` / `tick()`

Устаревшие глобалы. Замены: `task.wait`, `task.spawn`, `task.delay`, `os.clock` /
`DateTime.now().UnixTimestampMillis`. Старые вызовы не падают, поэтому живут годами и
ломают точность таймингов.

## 7. Проверка только в UI

```lua
-- ПЛОХО: кнопка неактивна, но remote всё равно принимает запрос
if coins >= price then
    buyButton.Visible = true
end
```

Эксплойт вызывает remote напрямую. Проверка обязана быть на сервере; UI — только
отображение.

## 8. `GetChildren()` в цикле кадра

Каждый вызов создаёт новую таблицу. Кэшировать и обновлять по `ChildAdded` /
`ChildRemoved`, а не опрашивать 60 раз в секунду.

## 9. Имя члена в нижнем регистре

`:findFirstChild(`, `:getchildren(`, `:waitforchild(` — не существуют. Возвращают `nil`,
а не ошибку, поэтому падает позже и в другом месте. `rbx_lint` ловит это правилом
`method-case`.

## 10. Один скрипт на 2000 строк «потому что так проще»

Один файл нельзя ни протестировать, ни переиспользовать, ни отревьюить. Сервисы —
`ModuleScript` с явным `start()`, точка входа — один `Bootstrap` на сторону.

## 11. `pcall` вокруг собственного кода

`pcall` нужен на границе (DataStore, HttpService, `require` чужого модуля). Внутри своего
кода он прячет баг, который потом всплывёт в другом месте с потерянным стеком.
