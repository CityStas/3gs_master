# Локальная генерация — в первую очередь

Правило проекта. Внутри `F:\Pets\Projects\local_tools\3GS_Master` (в первую
очередь `projects/games/<name>/`) свой арт делается **своей** связкой. Скачать готовое —
не грех, но это **второй** эшелон.

**Канонический источник правила — сам проект:**
`F:\Pets\Projects\local_tools\3GS_Master\ASSET-POLICY.md`
(и правила проекта — `AGENTS.md` в его корне). Этот скилл — операционная
выжимка; при расхождении верить проекту.

## 0. Лестница приоритетов

| # | Шаг | Что сюда попадает |
|---|---|---|
| 1 | **Локальная генерация** | персонажи, враги, боссы, оружие, предметы, ключевой арт, заставки, айдентика, сцены уровня |
| 2 | **Локальная генерация + постобработка** | апскейл, смена настроения, варианты, кроп под пропорции |
| 3 | **Скачать готовый ассет** | тайлы, паттерны, звук, шрифты, референс, временная заглушка |
| 4 | Спросить пользователя | неясно, к какому эшелону отнести |

**Почему локальная генерация первая.** Персонаж, враг или ключевая сцена, которые
уже стоят в чужой игре, обесценивают проект сильнее, чем сэкономленные полчаса.
Плюс: единый стиль, воспроизводимость по `seed`, отсутствие лицензионных
вопросов, согласованность пайплайна.

**Что нельзя:** `ImageGen`, `VideoGen`, любой hosted text-to-image / text-to-video.
Это не про запрет скачивания, а про то, что генерация должна быть своей.

**Скачивание — как не навредить:** лицензия прежде файла (запись в
`NOTICE`/`CREDITS`: источник, автор, лицензия, дата); CC0/CC-BY/MIT безопасно,
CC-BY-NC/ND — не тащить в игру, которая может продаваться; не тащить то, что
станет лицом игры (видно в меню/трейлере → это уже эшелон 1); приводить к
палитре проекта; сообщать пользователю, что скачано.

## 1. Маршрутизация движков

| Движок | Когда | Цена |
|---|---|---|
| **z-image-turbo** `sd-server` :8687 | **по умолчанию**: фоны, спрайты, сцены, пропы | ~20 с @768², ~45 с @1856×768, **3.8 ГБ VRAM** |
| ComfyUI `t2i` (Qwen-Image 2.1) | арт с **читаемой надписью** (заставка, титул, лого) | ~12 мин, 8.9 ГБ |
| ComfyUI `color_swap` | **точная** перекраска с сохранением формы | ~12 мин |
| ComfyUI `remove_bg_fast` (BiRefNet) | вырезание фона | 24 с |
| ComfyUI `edit` | правка по референсу | ~12 мин |
| Real-ESRGAN | увеличение готовой картинки | 1856×768 → 2× за 14 с; VRAM-арбитраж **не занимает** |
| ComfyUI `to_3d_high` (Pixal3D/TRELLIS.2) | **3D по умолчанию**: UV + PBR, реагирует на свет | ~17–18 мин |
| ComfyUI `to_3d_economy` (TripoSplat) | 3D-превью; **без UV**, игнорирует свет | ~3 мин |
| **Blender** `blender --background --python` | **DCC-шаг поверх GLB**: риг + анимация, ретопология/UV, GLB↔FBX, перебейк текстур, превью | headless; VRAM-арбитраж **не занимает** |
| Qwen2.5-VL-7B `bin/llama-mtmd` | «посмотри, что получилось» | ~5.5 ГБ VRAM |

Задача сама выбирает движок: `engine: "auto"` → `image` и `recolor` в z-image,
всё остальное в ComfyUI. Принудительно: `"engine": "comfy"` (надписи) или
`"engine": "z-image"`.

**3D: качество в приоритете.** `quality: "high"` — по умолчанию (~16–18 мин).
Скорость регулируется не понижением качества, а двумя полями:

- **`faces_3d`** — сколько граней оставить после `186 DecimateMesh`. В воркфлоу
  стоит `target_face_count: 700000` → **~40 МБ на проп**. Для 2D-игры, где спрайт
  занимает ~15 % высоты кадра, ставить **5 000–20 000**. Это не оптимизация, а
  обязательный шаг: 40 МБ на проп web-игра не переживёт.
- **`steps_3d`** — суммарно 56 шагов на 4 сэмплера (узлы 3/12/18/23 = 12/12/20/12).
  Время почти линейно: shape ~35–38 с/ит, texture ~18 с/ит.

**`resolution_3d` — НЕ рычаг** (проверено замером): 512 дал 1051.6 с / 698 448
граней / 40.2 МБ, 1024 — 955.7 с / 698 818 граней / 42.1 МБ. Разницы нет, 1024
вышел даже быстрее (первый прогон платил за холодную загрузку весов). Поле едет в
`312 ImageCropToMask`, то есть меняет размер входной картинки, а TRELLIS.2 всё
равно приводит её к своему внутреннему размеру.

**Blender — то, что ComfyUI не делает.** `to_3d_*` отдаёт **сырой** GLB и на этом
останавливается. Всё, что требует *редактирования* меша, идёт через Blender в фоне
(`blender --background --python <script.py>`): авто-риг + ретаргет анимации
(Kimodo / Mixamo / ARDY → наш меш), quad-ретопология и чистка UV, конвертация
GLB↔FBX↔OBJ, перебейк текстур, headless turntable-превью. Путь — `BLENDER_EXE`
(`cmd\_env.cmd`, `E:\Programs\Blender\blender.exe`, 5.2.2 LTS); наличие проверяет
`cmd\doctor.cmd` (строка `blender`). В арбитраже VRAM **не участвует** — как
Real-ESRGAN, headless-прогон держит сотни МБ и стоит рядом с ComfyUI. Не найден —
просто не предлагать риг/анимацию; картинки и 3D-меш это не ломает.

## 2. Маршрут запуска

```bash
cd F:/Pets/Projects/local_tools/3GS_Master
./.venv/Scripts/python.exe tools/generate.py --project projects/games/<name> --jobs <plan.json>
./.venv/Scripts/python.exe tools/generate.py --status     # кто держит карту
```

**Один запуск на весь список.** Каждый отдельный вызов — новый старт движка и
перезагрузка весов. Пак из восьми задач = один старт.

> MCP-сервер `assets` (`asset_generate_pack`) зарегистрирован только в
> `3GS_Master/.pi/mcp.json` — это конфиг pi, не WorkBuddy. Из WorkBuddy генерация
> идёт CLI-пакетом выше. Хочешь инструментом — перенести блок `assets` в
> `~/.workbuddy-ai/mcp.json` и нажать Trust.

## 3. Схема JSON-плана

```json
{
  "project": "F:\\Pets\\Projects\\local_tools\\3GS_Master\\projects\games\\my_game",
  "jobs": [
    { "kind": "image", "name": "far-back-2", "prompt": "…",
      "aspect_ratio": "21:9 (Ultrawide)", "megapixels": 1.5, "steps": 8, "seed": 11,
      "out": "Shrooms/level_1/raw/far_back_2.png" },

    { "kind": "image", "name": "splash", "engine": "comfy",
      "prompt": "title art with the words DedSpace 2D", "out": "menu_splash.png" },

    { "kind": "mask", "name": "mid-layer-2-cut", "from": "mid-layer-2",
      "out": "Shrooms/level_1/mid_layer.png" },

    { "kind": "upscale", "name": "far-back-2-x2", "from": "far-back-2", "scale": 2,
      "out": "Shrooms/level_1/raw/far_back_2@2x.png" },

    { "kind": "recolor", "name": "far-back-2-dusk", "from": "far-back-2",
      "strength": 0.5, "prompt": "the same scene at dusk, amber palette",
      "out": "Shrooms/level_1/raw/far_back_2_dusk.png" },

    { "kind": "3d", "name": "spore-shroom", "from": "spore-shroom-concept",
      "quality": "high", "faces_3d": 12000,
      "out": "Shrooms/level_1/3d/spore_shroom.glb" }
  ]
}
```

Поля (полностью — `threejs/assets/scheduler.py`, `Job.from_dict`, и README):

| поле | смысл |
|---|---|
| `kind` | `image` \| `mask` \| `3d` \| `upscale` \| `recolor` (алиасы: `t2i`, `nobg`, `mesh`, `character`, `esrgan`, `img2img`…) |
| `engine` | `auto` \| `z-image` \| `comfy` |
| `from` | **имя более ранней задачи пака** — так цепочка остаётся в одной сессии |
| `out` | путь относительно проекта. **Без него файл уедет в репозиторный `assets/`, а не в игру** |
| `megapixels` | реальный размер; на z-image-пути выводится из `aspect_ratio` + `megapixels` |
| `width`/`height` | явный размер для z-image (кратно 64), перебивает `aspect_ratio` |
| `resolution` | **только** подсказка text-encoder'у ComfyUI; на z-image не используется |
| `faces_3d` | сколько граней оставить у 3D-меша — **главный рычаг выхода** (дефолт графа 700 000 ≈ 40 МБ; ставить 5 000–20 000) |
| `steps_3d` | суммарные шаги 4 сэмплеров (56 по умолчанию) — линейный рычаг времени |
| `resolution_3d` | размер входной картинки для 3D. **Замером признан no-op** — не использовать как рычаг |
| `quality` | `high` (по умолчанию) \| `economy` |
| `scale` / `upscale_model` | для `upscale` |
| `strength` | для `recolor` (0.1–0.95) |
| `steps`, `seed`, `cfg`, `guidance`, `negative`, `steps_3d`, `fast`, `remove_bg_first` | переопределения |

**Порядок задач.** Движок переключается при смене: одна карта держит либо
sd-server, либо ComfyUI. Поэтому группировать — сначала все картинки, потом все
маски и 3D, а не чередовать.

## 4. Инвариант VRAM

```
не более одного из:  llama-server :8080   XOR   sd-server :8687   XOR   ComfyUI :8188
```

Real-ESRGAN — исключение (сотни МБ), он не считается.

- `--status` показывает владельца карты и `data/gen.lock`.
- Пока идёт пак, `llm :8080 : down` — норма, а не падение.
- `data/gen-status.json` — живой снапшот таймлайна.
- Не поднимать движок руками и не оставлять рядом с LLM.

## 5. Границы z-image img2img (`kind: "recolor"`)

Проверено вживую:

- **Inpaint нет.** `mask`/`mask_image` на `/sdapi/v1/img2img` принимаются и
  игнорируются для Z-Image.
- **`strength` торгует композицию на послушание.** На спрайте 768²: `0.25`
  сохранил силуэт почти точно, но палитру почти не сменил; `0.55` сменил палитру
  и пересочинил кадр. Настройки, которая делает и то и другое, нет.
- Размер источника **наследуется** (из PNG IHDR), поэтому пропорции не теряются.

Вывод: «тот же спрайт, другой цвет» → `color_swap` в ComfyUI. `recolor` — для
вариаций и смены настроения, где дрейф и есть цель.

## 6. Мониторинг

```bash
./.venv/Scripts/python.exe tools/generate.py --status
tail -40 logs/generate.log                                    # job_begin / job_end / engine=
tail -c 1200 logs/comfy-sidecar.log | tr '\r' '\n' | tail -12  # прогресс ComfyUI
tail -c 600 logs/sd-sidecar.log | tr '\r' '\n' | tail -6       # загрузка z-image
cat data/gen-status.json
```

`comfy-sidecar.log` пишет через `\r` — читать только после `tr '\r' '\n'`. И
помнить: он **дописывается**, поэтому хвост может показывать прогресс прошлого
прогона; сверять со временем старта в `generate.log`.

## 7. Постобработка

Сгенерированное — сырьё, а не готовый слой:

1. Кроп под пропорции уровня + **равномерный** скейл (без растяжения).
   Образец: `tools/level1_fit.py` (21:9 → 3:1, 2170×725).
2. Разложить по путям, которые ждёт сцена, а не по дефолтному `assets/images/`.
3. Проверить, что сцена их видит: 404 на новый путь — частая причина
   «нарисовали, а на экране старое».

## 8. Грабли

- **404 на новые пути** — сцена отрабатывает раньше, чем файлы появились. Сектор
  обязан быть необязательным.
- **Прогресс в логе отстаёт** — tqdm буферизуется; верить mtime файла лога.
- **Долгая тишина в пакете** — штатно. Не ретраить: повторный запуск встанет на локе.
- **Свежесть сборки по размеру pck не проверить** — правка float-значений не
  меняет размер; смотреть mtime и содержимое.
- **`tools/` не попадает в web-экспорт** при `export_filter="resources"` — новый
  скрипт вписывать в `export_files`, проверять по логу `grep "Storing File:"`.
- **Первая генерация после старта sd-server дорогая** (~60–75 с): ленивое
  построение графа. Вторая и дальше — ~20 с. Не считать это регрессом.
- **Старт ComfyUI — ~47 с, а не ~7 мин.** Все ноды наших воркфлоу оказались
  родными (`comfy_extras/`), поэтому клиент стартует с
  `--disable-all-custom-nodes --whitelist-custom-nodes ComfyUI-GGUF` и не платит
  ~250 с за импорт 25 сторонних паков (`ComfyUI-Trellis2` — 118 с,
  `ComfyUI-Easy-Use` — 60 с). Список — `config.COMFY_CUSTOM_NODES`,
  `THREE_COMFY_CUSTOM_NODES=*` возвращает «грузить всё». Новый воркфлоу с
  незнакомым паком падает **громкой 400 с именем класса**, а не тихой порчей
  картинки — если увидел такое, допиши папку в список.
- **После перезагрузки первый z-image дороже на ~15–50 с** — mmap-фолт 4.5 ГБ
  gguf идёт на скорости диска (~100 МБ/с). Прогресс-бар с `MB/s` в
  `sd-sidecar.log` — это фолт весов, а не сэмплинг.
- **`taskkill /PID` из Git Bash** ломается о конвертацию путей — нужен
  `MSYS_NO_PATHCONV=1`.
- **Процесс, запущенный из шелла, умирает вместе с ним** — sd-server поднимать
  detached (это уже делает `SdServer.start()`).
- **Отчёт** — перечислять `files` из отчёта, а не список задач. Если задача упала,
  сказать какая и почему; остальные всё равно завершились.
