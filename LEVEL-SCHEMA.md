# Формат уровня: `level.json`

**Читать до того, как писать или править любой `level*.json`.** Документ описывает  
не «как хотелось бы», а то, что реально понимает код: `web3d/scene.js` строит из  
этого файла сцену, `web3d/engine.js` — физику и логику. Если документ разойдётся с  
кодом, прав код: сверяйтесь с `scene.js`, функция `buildVisual` (типы узлов) и  
`layerDepth` (слои), и с `engine.js`, класс `World` (коллайдеры).

Проверка после записи:

```bash
python tools/level_lint.py projects/games/<имя>/web3d/level.json
```

Линтер ловит всё из раздела «Три вещи, которые ломаются чаще всего» и возвращает  
код 1, если уровень нерабочий.

---

## 0. Три вещи, которые ломаются чаще всего

| Сделано                                                         | Что происходит на самом деле                                                                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `textures` с ключом-**именем**: `{"example_tex": {"url": "…"}}` | `scene.js` грузит `TEX_ROOT + ключ`, то есть запрос уходит на `/example_tex` → **404 в консоли**, спрайт молча остаётся без текстуры |
| узел ссылается на `props.sprite` вместо `props.texture`         | `buildVisual` не находит свою ветку → **узел не рисуется вообще**, и в консоли тоже пусто                                            |
| у узла нет поля `children`                                      | в `scene.js` стоит `for (const child of node.children)` **без фолбэка** → `TypeError`, сцена не строится целиком                     |

Все три ошибки тихие или почти тихие. Именно поэтому нужен линтер, а не «посмотрю  
глазами».

---

## 1. Каркас файла

```json
{
  "project":  { "name": "…", "viewport": [1280, 720], "clear_color": [0.02, 0.02, 0.05, 1.0] },
  "textures": { "путь/от/корня/игры.png": [ширина, высота] },
  "frames":   { "SET_A": { "ANIM_A": { "frames": ["<path>/frame_00.png"] } } },
  "tree":     { "type": "Node2D", "name": "Main", "path": "Main", "props": {}, "children": [] }
}
```

Все четыре ключа обязательны. `textures` и `frames` могут быть пустыми объектами  
`{}` — но ключи должны существовать: `scene.js` вызывает `Object.keys()` на них без  
проверки.

---

## 2. `project`

| Поле             | Обязательно | Смысл                                                                                                                   |
| ---------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| `clear_color`    | **да**      | `[r, g, b, a]`, sRGB, 0..1. Фон сцены. `scene.js` читает `project.clear_color.slice(0,3)` без защиты — без него падение |
| `name`           | нет         | подпись, ни на что не влияет                                                                                            |
| `viewport`       | нет         | `[w, h]` виртуального кадра. По умолчанию `[1280, 720]`. Влияет на то, как кадр вписывается в окно                      |
| `backdrop_color` | нет         | **нигде не читается**, оставлено исторически                                                                            |

Цвета — **sRGB**, как их видно в исходнике. `scene.js` переводит их через  
`setRGB(..., SRGBColorSpace)`; если записать линейные значения, фон уедет по яркости  
вдвое.

---

## 3. `textures` — словарь «путь → размер»

```json
"textures": {
  "web3d/assets/example_tex.png": [1024, 512],
  "artsets/SET_A/far.png": [2170, 725]
}
```

- **Ключ — путь к файлу относительно КОРНЯ ИГРЫ** (каталога, внутри которого лежит  
  `web3d/`), а не имя, не id и не URL. `scene.js` грузит `TEX_ROOT + ключ`, где  
  `TEX_ROOT = '../'`, потому что страница живёт в `web3d/`. Из корня игры это  
  совпадает с путём в ключе.
- **Значение — `[ширина, высота]` в пикселях.** Оно становится размером плоскости  
  (`PlaneGeometry`). Размер берётся ИЗ ФАЙЛА, а не из картинки, поэтому совпадение  
  обязательно: ошибётесь — спрайт растянется или сожмётся.
- **Объекта с `url`/`repeat`/`offset` здесь нет.** `repeat` и `offset` — это свойства  
  узлов (`Parallax2D.repeat_size`, `Sprite2D.offset`), а не текстуры.
- Ключ, на который никто не ссылается, всё равно загружается — лишние записи просто  
  тратят трафик. Ключ, на который ссылаются, но которого нет, — тихий пропуск узла.

---

## 4. `frames` — анимации

```json
"frames": {
  "SET_A": {
    "ANIM_A": { "frames": ["<path>/a_00.png", "<path>/a_01.png"],
                "loop": true, "speed": 10 },
    "ANIM_B": { "frames": ["<path>/b_00.png"], "loop": true, "speed": 14 }
  }
}
```

- Ключ верхнего уровня (`SET_A`) — это **имя набора**, на него ссылается узел  
  `AnimatedSprite2D` через `props.frames`.
- Внутри — анимации: имя (`ANIM_A`, …), список кадров (пути от корня игры),  
  `loop`, `speed` (кадров в секунду).
- Узел выбирает анимацию через `props.animation` (или `props.autoplay`). Если не  
  указать — берётся первая по порядку ключей.
- Размер спрайта берётся из **файла кадра** (`tex.image.width/height`), а не из  
  `textures`. Поэтому кадры не нужно регистрировать в `textures`.
- Пустой набор или набор без кадров = узел не рисуется.

---

## 5. `tree` — дерево узлов

Каждый узел:

```json
{ "type": "Sprite2D", "name": "Sprite", "path": "Player/Sprite", "props": {}, "children": [] }
```

| Поле       | Обязательно | Смысл                                                                     |
| ---------- | ----------- | ------------------------------------------------------------------------- |
| `type`     | **да**      | что узел делает (таблица ниже)                                            |
| `name`     | **да**      | имя узла; по нему ищут `Player`, `Camera2D`                               |
| `props`    | **да**      | объект свойств; может быть `{}`                                           |
| `children` | **да**      | массив детей; `[]` если нет. **Без него падение**                         |
| `path`     | нет         | полный путь через `/`. Если нет — достраивается по дереву (`parent/name`) |

`path` нужен там, где имена не уникальны: у `Player`, `EnemyLeft` и `Boss` ребёнок  
называется одинаково — `Sprite`, и по одному имени их не различить.

### Общие `props`

| Ключ       | Тип        | Смысл                                                                                                            |
| ---------- | ---------- | ---------------------------------------------------------------------------------------------------------------- |
| `position` | `[x, y]`   | позиция **относительно родителя** (накапливается вниз по дереву). Нет `position` — узел в точке `(0,0)` родителя |
| `scale`    | `[sx, sy]` | масштаб узла. Знак не инвертируется вместе с осью Y                                                              |
| `z_index`  | число      | сдвиг порядка отрисовки внутри родителя. Может быть дробным                                                      |

---

## 6. Типы узлов

| `type`               | Обязательные `props` | Что делает                                                                                   |
| -------------------- | -------------------- | -------------------------------------------------------------------------------------------- |
| `Node2D`             | —                    | пустая группа. Обычный контейнер                                                             |
| `StaticBody2D`       | —                    | группа; вложенные в неё коллайдеры становятся **твёрдыми**                                   |
| `CharacterBody2D`    | —                    | группа персонажа (для `scene.js` — то же, что `Node2D`)                                      |
| `Area2D`             | —                    | группа-зона; **не** твёрдая (пикапы, хит-зоны)                                               |
| `Sprite2D`           | `texture`            | плоскость размером из `textures[texture]`. Доп.: `offset`, `flip_h`, `flip_v`                |
| `AnimatedSprite2D`   | `frames`             | кадр анимации. Доп.: `animation`, `offset`                                                   |
| `ColorRect`          | `color`, `rect`      | заливка. `rect` = `[left, top, right, bottom]` **в локальных координатах вокруг `position`** |
| `Parallax2D`         | —                    | слой параллакса. `scroll_scale` `[sx, sy]`, `repeat_size` `[шаг, …]`, `repeat_times`         |
| `CollisionShape2D`   | `shape.size`         | отладочный прямоугольник; внутри `StaticBody2D` — коллайдер                                  |
| `CollisionPolygon2D` | `polygon`            | отладочный контур; внутри `StaticBody2D` — рельеф                                            |
| `Camera2D`           | —                    | лимиты камеры. `limits` `{limit_left, limit_top, limit_right, limit_bottom}`, `offset`       |

Дополнительно к таблице:

- **`CollisionShape2D`**: `shape` — объект `{"size": [w, h]}`, размер **полный**  
  (не половина), вокруг `position` узла.
- **`CollisionPolygon2D`**: `polygon` — **плоский** массив `[x0, y0, x1, y1, …]`,  
  не список пар. Строится от `position` узла.
- **`Camera2D`**: ищется по всему дереву через `find`, где угодно. `offset`  
  прибавляется **после** клампа по лимитам. `Player/Camera2D` — принятое место.
- **`ColorRect`**: `color` — `[r, g, b, a]`, sRGB. `rect` — вокруг `position`:  
  прямоугольник `[-90, -26, 90, 26]` при `position [420, 470]` нарисуется от  
  `(330, 444)` до `(510, 496)`.
- **`Parallax2D`**: его `children` рисуются один раз, а потом размножаются копиями с  
  шагом `repeat_size[0]` в диапазоне `-repeat_times .. +repeat_times`. Слой  
  **обязан** лежать в корне дерева: глубина параллакса считается от `scroll_scale`.

**`Player`**: точка старта игрока — это `find(tree, n => n.name === 'Player' && n.props.position)`.  
Если такого узла нет, старт `[40, 464]`. То есть у `Player` **обязан** быть `position`,  
иначе игра начнётся в произвольном месте.

## 7. Координаты, слои и порядок отрисовки

- **Ось Y направлена ВНИЗ** (как читаются числа глазами). В three.js знак  
  переворачивается ровно в одном месте — при выставлении позиции: `three.y = -level.y`.
- **Позиции относительны родителю** и накапливаются. `Platforms/Ground` с  
  `position [1280, 660]` при родителе в `(0,0)` окажется в `(1280, 660)`.
- **z-буфера нет.** Порядок задаёт одно число `renderOrder`, равное `depth`:
  - **корневой узел дерева** получает глубину **по своему имени**: `depth = layerDepth(name)`;
  - **все остальные** — `depth = depth(родителя) + z_index`.
  | Имя корневого узла                    | `depth` |
  | ------------------------------------- | ------- |
  | `Backdrop`                            | −10000  |
  | `GameplayLayer`, `GameplayLayer2`     | −800    |
  | `Platforms`                           | −600    |
  | `Props2`                              | −400    |
  | `Player`, `EnemyLeft`, `Boss`         | 0       |
  | любое другое (в т.ч. `Main`, `Props`) | −100    |
  Меньше число — дальше от зрителя.

  **Важно, и это неочевидно.** `scene.js` считает глубину по имени только для  
  самого верхнего узла дерева (`parentObj === this.root`). Обычно корень зовётся  
  `Main` и получает −100, а `Backdrop`, `Platforms` и прочие слои — его **дети**,  
  и таблица им ничего не даёт: они все получают `−100 + z_index`, то есть при  
  пустом `z_index` — одинаковую глубину. При равной глубине порядок задаёт  
  порядок в `children`, и это работает, но хрупко.

  **Поэтому `z_index` слоям ставьте явно.** Рабочий набор значений:
  | Слой                             | `z_index` |
  | -------------------------------- | --------- |
  | `Backdrop`                       | −200      |
  | `FarBackground` (параллакс 0.25) | −100      |
  | `FarMidLayer` (0.38)             | −99       |
  | `MidLayer` (0.5)                 | −98       |
  | `GameplayLayer`                  | −40       |
  | `Props`                          | −38       |
  | `Enemies`                        | −4        |
  | `Player`                         | 0         |
  `z_index` сдвигает **всё поддерево**, поэтому «положить площадку перед землёй»  
  одним `z_index` у площадки не выйдет: сначала должен быть правильный родитель.
- **`Parallax2D`**: глубина от `scroll_scale` тоже достаётся только корневому  
  узлу. Вложенному слою ставьте `z_index`.

## 8. Что правит студия, а что нет

- Правимый узел **обязан иметь `props.position`** — редактор двигает только её.
- Узлы с именами `Backdrop`, `GameplayLayer*`, `Terrain*`, `WallLeft`, `WallRight`,  
  `Ceiling`, `Strip` **не правятся вовсе**, и запрет распространяется на всё  
  поддерево: их позиция вычисляется, а не задаётся руками.
- Поэтому фон кладём под `Backdrop`, а всё подвижное — под `Platforms`/`Props`/`Player`.
- Правки студии **не пишутся в `level.json`**: они ложатся в `<level>_edit.json`  
  рядом и накладываются при пересборке. Прямая правка `level.json` тоже работает,  
  но при следующей пересборке (только у игр с `builder: level_build`, которые  
  собираются из таблиц арта) её затрёт.

## 9. Минимальный рабочий уровень


Полный файл, который строится и играется. Всё, что здесь есть, обязательно; всё,  
чего нет, — опционально.

```json
{
  "project": {
    "name": "my game",
    "viewport": [1280, 720],
    "clear_color": [0.06, 0.07, 0.10, 1.0]
  },
  "textures": {},
  "frames": {},
  "tree": {
    "type": "Node2D", "name": "Main", "path": "Main", "props": {},
    "children": [
      { "type": "Node2D", "name": "Backdrop", "path": "Backdrop",
        "props": { "z_index": -200 }, "children": [
          { "type": "ColorRect", "name": "Sky", "path": "Sky",
            "props": { "rect": [0, 0, 2560, 720], "color": [0.06, 0.07, 0.10, 1.0] },
            "children": [] }
        ] },
      { "type": "Node2D", "name": "Platforms", "path": "Platforms",
        "props": { "z_index": -100 }, "children": [
          { "type": "StaticBody2D", "name": "Ground", "path": "Platforms/Ground",
            "props": { "position": [1280, 660] },
            "children": [
              { "type": "CollisionShape2D", "name": "CollisionShape2D",
                "path": "Platforms/Ground/CollisionShape2D",
                "props": { "shape": { "size": [2560, 80] } }, "children": [] }
            ] }
        ] },
      { "type": "CharacterBody2D", "name": "Player", "path": "Player",
        "props": { "position": [160, 560], "z_index": 0 },
        "children": [
          { "type": "CollisionShape2D", "name": "CollisionShape2D",
            "path": "Player/CollisionShape2D",
            "props": { "shape": { "size": [40, 60] } }, "children": [] },

```

## 10. Манифест `web3d/levels.json`

Уровень, не вписанный в манифест, студия и игра не увидят. Геометрия в манифест  
**не дублируется** — только описание.

```json
{
  "start": "level_0",
  "levels": {
    "level_0": {
      "file": "level.json",
      "editable": true,
      "title": "LEVEL 0",
      "subtitle": "my game",
      "objective": "EDIT ME",
      "door": { "x": 0.0, "y": 0.0, "half": 64, "gate": "" },
      "fall_y": 900,
      "next": ""
    }
  }
}
```

- `file` — путь от `web3d/` (`level.json`, либо `<level_dir>/level.json`).
- `editable: true` — уровень можно выравнивать в студии. Без этого «Сохранить»  
  выключено.
- `door` и `fall_y` читает игровой слой (`engine.js`), а не студия.

## 11. Порядок работы

1. Прочитать этот файл.
2. Понять, какие ассеты нужны, и сгенерировать их **одним паком**  
   (`ASSET-POLICY.md`, `cmd\gen.cmd`) — до того, как писать `level.json`.
3. Записать `level.json` (или правки в студию — тогда `<level>_edit.json`).
4. `python tools/level_lint.py <путь>` — код возврата 0.
5. Открыть в студии и посмотреть глазами: линтер проверяет схему, а не замысел.
