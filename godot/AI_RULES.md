# AI_RULES.md — правила проекта для агента

Отдельный от `AGENTS.md` файл с настраиваемыми правилами конкретного Godot-проекта.
**Заполняется под проект.** Пока проект не выбран, здесь только общий каркас.

Правила в этом файле объясняют не API Godot, а **соглашения проекта**.
Всё, что относится к API движка, живёт в RAG, а не здесь.

---

## Именование

- Узлы: `PascalCase` (`PlayerCamera`, `HUDLayer`)
- Скрипты: `snake_case.gd` (`player_controller.gd`)
- `class_name`: `PascalCase`
- Функции/переменные: `snake_case`
- Приватные: `_leading_underscore`
- Константы: `SCREAMING_SNAKE_CASE`
- Сигналы: `snake_case`, прошедшее время (`health_changed`, `item_collected`)

## Владение узлами (node ownership)

- Одна ответственность на узел. Компоненты (`HealthComponent`, `HitboxComponent`)
  — дети того, кем управляют.
- Корень сцены владеет всей сценой; никаких `get_node("../../..")` из глубины.
- Кросс-сценовое взаимодействие — только через сигналы или автолоады.

## Структура сцен

```
res://
  scenes/        # .tscn по функциональности
  scripts/       # .gd, зеркалит scenes/
  resources/     # .tres
  assets/        # спрайты, звук, шрифты
  autoload/      # синглтоны
```

## Архитектура

- Автолоады — только для действительно глобального (GameState, AudioManager, EventBus).
  Не делать автолоадом то, что может быть узлом в сцене.
- Направление зависимостей: сцена → компонент → утилита. Никаких циклов.
- `class_name` не создавать для классов, используемых в одном файле.

## Сигналы

- Имена — прошедшее время, без `on_` в имени сигнала (`died`, не `on_died`).
- Обработчики — `_on_<node>_<signal>` (`_on_start_button_pressed`).
- Подключение в сцене (редактор) предпочтительнее кода, когда связь статична.

## Стиль

- Один отступ — табы (стандарт Godot).
- Строки — двойные кавычки.
- Максимум ~100 символов в строке.
- Ранний выход вместо глубокой вложенности.

## Тестирование

- После каждой правки — `godot_validate()` + `godot_run_scene()`.
- Новая сцена должна запускаться в headless без ошибок.
- Не считать фичу готовой без прогона.

## Бюджеты производительности

- `_process` только там, где реально нужен покадровый апдейт.
- Не более N активных физических тел одновременно (заполнить под проект).
- Никаких аллокаций в `_process`.

## Политика ассетов

- Ассеты не добавляются агентом: он работает с тем, что уже импортировано.
- Новые ресурсы — только текстовые (`.gd`, `.tscn`, `.tres`).

## Что агент может менять

- `*.gd`, `*.tscn`, `*.tres`, `*.cfg`, `*.md` внутри проекта.

## Что агент менять НЕ может

- `project.godot` — только по явному запросу пользователя.
- `addons/`, `*.import`, `.godot/` — не трогать.
- Бинарные ассеты — не трогать.
- Файлы вне корня проекта — недоступны по архитектуре.
