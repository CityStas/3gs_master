# Порядок источников и маршрутизация запроса

Статус: знания. Правила того, **где искать** — применяются, когда инструмент поиска есть.

## Порядок по умолчанию

```
1. Godot Asset Store
2. Poly Haven
3. Kenney
4. Quaternius
5. itch.io
6. OpenGameArt
7. GameDev Market
```

Порядок — не вкусовщина. Он отражает три фактора сразу: совместимость с Godot,
чистоту лицензии и предсказуемость импорта. Godot Asset Store первый потому, что ассет
там уже под Godot. Poly Haven второй, потому что всё CC0 и есть API. itch.io пятый
несмотря на размер каталога, потому что лицензии там неоднородны.

## Маршрутизация по интенту запроса

Порядок из семи пунктов выше — общий. На практике сначала определяется **тип запроса**,
и только потом внутри своей ветки работает порядок.

### Ветка A — Godot-специфичное: аддон, плагин, инструмент, шейдер, шаблон

```
Godot Asset Store  ->  (ничего больше)
```

Идти только в магазин. Спрайтовый источник тут не поможет: нужен код, интегрированный
с движком, с указанной версией.

Примеры: «нужна диалоговая система», «нужен редактор тайлмапов», «нужен water shader»,
«нужен addon для сохранений».

### Ветка B — 3D: модель, PBR-материал, HDRI, окружение

```
Poly Haven  ->  Quaternius  ->  Kenney
```

Poly Haven первый: CC0, API, и HDRI-окружение сразу решает вопрос освещения.
Quaternius — когда нужны low-poly персонажи и объекты. Kenney — когда нужен
3D-контент в его плоском стиле (у него есть и 3D-наборы).

### Ветка C — 2D: спрайты, тайлсеты, UI, иконки

```
Kenney  ->  itch.io  ->  OpenGameArt
```

Kenney первый: CC0, единый стиль, все нужные категории. itch.io — когда в Kenney
нет подходящего стиля (например, нужен пиксель-арт конкретного жанра). OpenGameArt —
когда нужен старый классический материал.

### Ветка D — звук

Отдельного приоритетного источника в списке нет. Звук ищется по тем же каталогам
(itch.io, OpenGameArt), с проверкой лицензии по тем же правилам. Предпочтительные
форматы — в `05_search_and_scoring.md`.

## Правило одного запроса — одного источника

Не обходить все семь источников подряд. Определить ветку, проверить первый источник
ветки, и только если там нет — идти дальше. Причина практическая: ответ «проверил все
семь» дорогой, а ответ «в Kenney есть ровно то, что нужно» — короткий и полезный.

## Приоритет: локальное выше внешнего

Перед любым внешним поиском — проверить, нет ли ассета уже в проекте или в локальном
манифесте. Порядок:

```
1. Уже есть в проекте (res://assets/, прогретый ранее манифест)
2. Уже скачано ранее (запись в manifest, ассет лежит в res://assets/external/)
3. Внешний источник по ветке A/B/C/D
```

Причина — в `04_manifest.md`: повторное скачивание того же ассета это дедупликация,
потраченное время и разъехавшиеся версии файлов в проекте.

Формулировка для пользователя, когда ассет уже есть: «У нас уже есть sci-fi дверь —
беру её, а не тяну заново.» Это и есть правильное поведение манифеста.
