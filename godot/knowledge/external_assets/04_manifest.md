# Manifest внешнего ассета (`asset.json`)

Статус: знания. Схема файла, который обязан лежать рядом с каждым внешним ассетом.

## Зачем манифест вообще нужен

Пять причин, все практические:

1. **Поиск по своим.** «У нас уже есть sci-fi дверь» — вместо повторного скачивания
   того же ассета из интернета. Без манифеста агент не знает, что уже принесено.
2. **Проверка целостности.** `sha256` отвечает на вопрос, тот ли это файл, и не побился ли он.
3. **Атрибуция.** Для CC-BY это не «хорошо бы», а требование лицензии.
4. **Устаревание.** Видно, когда ассет принесён и откуда; при ревизии проекта можно
   проверить, жива ли исходная ссылка и не сменилась ли лицензия.
5. **Безопасное удаление и дедупликация.** Знать, что именно принадлежит внешнему
   ассету, — единственный способ удалить его, не задев авторские файлы проекта.

## Схема

```json
{
  "name": "Sci-Fi Container",
  "source": "kenney",
  "source_url": "https://kenney.nl/assets/...",
  "download_url": "https://.../scifi-container.glb",
  "license": "CC0",
  "author": "Kenney",
  "original_filename": "container.glb",
  "downloaded_at": "2026-10-06T11:23:00Z",
  "sha256": "<64 hex chars>",
  "formats": ["glb"],
  "tags": ["sci-fi", "container", "low-poly", "prop"],
  "godot_compatibility": "4.x"
}
```

## Поля

| Поле | Обязательно | Зачем |
|---|---|---|
| `name` | да | человекочитаемое имя, по нему ищет агент |
| `source` | да | имя источника, один из семи (см. `01_sources.md`) |
| `source_url` | да | страница ассета — нужна для атрибуции |
| `download_url` | да | прямая ссылка на файл, а не страница |
| `license` | да | без неё ассет не устанавливается |
| `author` | для CC-BY | для строки атрибуции |
| `original_filename` | да | имя до переименования; помогает найти в исходном паке |
| `downloaded_at` | да | дата получения |
| `sha256` | да | хеш файла |
| `formats` | да | расширения внутри ассета |
| `tags` | нет | улучшает поиск по локальному манифесту |
| `godot_compatibility` | да | под какую ветку Godot |

Обязательность `license` и `author` — не формальность. Ассет без записи о лицензии
считается непригодным для установки, и правильно считать его таким.

## Где лежит

Ассет и его манифест хранятся вместе, под папкой пакета:

```
res://assets/external/<pack_name>/
    asset.json          <-- манифест
    <файлы ассета>
```

Смысл «вместе»: удаление папки удаляет ассет и его следы одновременно; невозможно
осиротеть манифесту или потерять лицензию при переносе ассета.

Всё внешнее лежит **только** под `res://assets/external/`. Это позволяет в любой момент
ответить на вопрос «что в проекте пришло извне» одной операцией по папке и не смешивать
чужое с авторским.

## Что записывать во время работы

Порядок неслучаен: проверка идёт до записи.

```
1. скачать во временную папку (НЕ сразу в проект);
2. определить реальный тип файла;
3. посчитать sha256;
4. проверить, что тип соответствует ожидаемому;
5. только теперь перенести в res://assets/external/<pack>/;
6. записать asset.json;
7. импортировать в Godot;
8. проверить, что ассет открывается.
```

Пункт 1 важен: скачивание напрямую в проект означает, что при обрыве или мусорном
файле в `res://` появится неопознанный бинарник, который Godot попытается импортировать.

## Дедупликация

Два ассета считаются одним и тем же, если совпадают:

- `sha256` — точно тот же файл;
- либо `name` + `source` — тот же ассет, принесённый повторно.

В обоих случаях второй раз не скачивать: сообщить, что ассет уже есть, и использовать
существующий. Это прямая экономия и защита от разъехавшихся копий.

## Связь с RAG

В RAG попадают **только метаданные** из `asset.json` — никогда сам бинарник.
Подробности и обоснование — в `05_search_and_scoring.md`.
