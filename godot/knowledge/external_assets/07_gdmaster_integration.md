# Встраивание в gdmaster: что есть и чего нет

Статус: описание реального состояния репозитория. Раздел объясняет агенту, что
из ассетных возможностей включено, что собрано но выключено, и почему.

## Текущее состояние: три слоя

```
СЛОЙ 1 — ЗНАНИЯ            ЕСТЬ
  knowledge/external_assets/*.md     <-- этот раздел
  .pi/skills/godot-assets/SKILL.md   <-- workflow-скилл
  .pi/SYSTEM.md, раздел EXTERNAL ASSETS

СЛОЙ 2 — ВОЗМОЖНОСТЬ       СОБРАН, ВЫКЛЮЧЕН
  gdmaster/assets/                   адаптеры Poly Haven / Kenney / Godot Store,
                                     netguard, downloader, licenses, installer, manifest
  gdmaster/mcp/asset_mcp_server.py   8 инструментов asset_*
  policy_gateway.py                  четвёртый дочерний сервер — только при включении

СЛОЙ 3 — ГРАНИЦА           ЗАМОРОЖЕН
  ALLOWED_TOOLS                      23 имени Godot + RAG; asset_* НЕ входят
```

Наличие слоя 1 не создаёт слой 2. Знание того, как скачивать, не является
возможностью скачивать. Это разные вещи, и агент обязан их различать.

Слой 2 написан и проверен живыми запросами, но **выключен по умолчанию**:
у модели нет ни одного `asset_*` инструмента, пока пользователь не включит
набор. Выключено — значит выключено на уровне `ALLOWED_TOOLS`, а не в тексте
промпта.

## Почему скачивание сейчас невозможно механически

Дело не в промпте. Дело в коде.

**Фиксированный список инструментов.** Policy Gateway — единственный сервер, который
видит модель. Он опрашивает дочерние серверы, отдаёт только имена из allowlist и
отклоняет всё прочее ответом `TOOL_DENIED`. Сетевого имени в allowlist нет:

```
rag_search, rag_status,
godot_project_info, godot_list_files, godot_read_file,
godot_scene_tree, godot_script_symbols, godot_find_symbol,
godot_write_script, godot_patch_script,
godot_scene_create, godot_scene_add_node, godot_scene_remove_node,
godot_scene_set_property, godot_scene_attach_script,
godot_scene_connect_signal, godot_input_action_add, godot_project_init,
godot_validate, godot_run_scene,
godot_play_scene, godot_stop_play, godot_check_project
```

23 имени: 21 у Godot-сервера плюс 2 у RAG-сервера. Ни одного сетевого.

**Ограничение путей.** Слой путей отвергает буквы дисков, UNC-пути, переменные
окружения, `user://` и любой выход за корень проекта через `..`. Разрешённые расширения
для записи — только текстовые:

```
.gd .tscn .tres .godot .gdshader .shader .json .cfg .md .txt .gdshaderinc
```

Бинарных (`.png`, `.jpg`, `.wav`, `.ogg`, `.glb`, `.fbx`) здесь нет. То есть даже
если бы байты откуда-то взялись, записать их в проект через существующий путь нельзя.

**Вывод.** Скачивание невозможно на двух независимых уровнях: нет сетевого инструмента
и нет пути записи бинарников. Поэтому утверждение «я скачал ассет» — ложь по построению.

## Что уже появилось в слое 2

```
gdmaster/assets/                     НОВЫЙ ПАКЕТ
  adapters/base.py       интерфейс адаптера (search/inspect/license/resolve_bundle)
  adapters/godot_store.py  приоритет 1: аддоны, плагины, шейдеры
  adapters/polyhaven.py    приоритет 2: 3D-модели, PBR, HDRI (всё CC0, есть API)
  adapters/kenney.py       приоритет 3: 2D, звук, прототипы (CC0, разбор HTML)
  registry.py            единая точка перечисления источников
  netguard.py            Барьер 1: домены, схемы, приватные адреса, редиректы, размеры
  downloader.py          Барьер 2: поток в файл, точный счёт байт, sha256, комплекты
  installer.py           Барьер 3: распаковка, zip-slip, zip-bomb, только assets/external
  licenses.py            Барьер 4: решение по лицензии принимает КОД, не модель
  manifest.py            asset.json, дедупликация по sha256

gdmaster/mcp/asset_mcp_server.py     8 инструментов asset_*
```

Проверенные живыми запросами источники: Poly Haven API (модели/текстуры/HDRI),
Kenney (каталог + прямые ссылки на zip), Godot Asset Store (поиск + 302 на
предподписанный S3).

## Как включить слой 2

Одна переменная окружения в лаунчере:

```
set GDM_ENABLE_ASSET_TOOLS=1
```

Тогда гейтвей поднимает четвёртый дочерний сервер `assets`, и tool surface
становится 23 -> 31. Инструменты, которые получает модель:

```
asset_search     поиск во всех источниках сразу
asset_inspect    подробности ассета, включая лицензию
asset_license    лицензионное решение (принимает код)
asset_download   скачать комплект во ВРЕМЕННУЮ папку, не в проект
asset_install    перенести скачанное в res://assets/external/<pack>/
asset_remove     удалить установленный пакет
asset_list       что установлено
asset_manifest   манифест пакета: автор, лицензия, sha256
```

Установка двухшаговая намеренно: `asset_download` проверяет лицензию и пишет во
временную папку вне проекта, `asset_install` переносит уже проверенное. Мусорный,
битый или нелицензионный ассет не может попасть в проект «случайно».

## Что ещё не сделано

```
v2: Quaternius + OpenGameArt + GameDev Market
позже: indexer/retriever для метаданных ассетов, дедупликатор, база контрольных сумм
```

Реестр (`registry.py`) и сетевой guard (`netguard.ALLOWED_HOSTS`) — точки
расширения: новый источник добавляется регистрацией класса и домена, без
изменения инструментов и их схем.

itch.io сознательно НЕ подключён: у него нет API, загрузки часто за формой, а
автоматический вход под учётными данными пользователя — красная линия политики §17.

## Что делать агенту прямо сейчас

Слой 2 выключен, значит:

1. **Не выдумывать.** Не заявлять о поиске, скачивании, установке, которых не было.
2. **Быть полезным по-другому.** Назвать источник и ссылку, объяснить выбор, указать
   лицензию и требования, дать план импорта.
3. **Различать знание и возможность.** Уметь объяснить, почему сейчас нельзя, — и это
   нормальный ответ, а не отказ от работы.
4. **Указывать, что нужно изменить.** Если возможности нужны — назвать переменную
   `GDM_ENABLE_ASSET_TOOLS=1` и то, что она открывает (выход в интернет и запись
   бинарников в проект). Включение — решение пользователя, не твоё.
