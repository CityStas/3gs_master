# Модели: реестр, роутер, переключение в pi

Одна модель на все движки больше не нужна. `:8080` теперь держит **llama.cpp router
mode** (build b11435): один процесс, INI-реестр, все id в `/v1/models`, загрузка по
первому запросу, вытеснение LRU при `--models-max`.

## Как это устроено

```
models/llm-overrides.json      ручные правки (единственный файл, который стоит править)
        |
        v
tools/llm_models.py            сканирует GGUF, читает метаданные, считает контекст
        |                      (tools/gguf_meta.py - разбор заголовка GGUF без зависимостей)
        +--> models/llm-preset.ini      реестр роутера: [id] + model + ctx-size + сэмплинг
        +--> models/llm-registry.json   те же факты для doctor/бенчмарка/чтения глазами
        +--> pi-home*/models.json       провайдер `3gs`, ВСЕ id (pi-home, -three, -godot, -unity, -roblox)
        +--> ~/.pi/agent/models.json    провайдер `3gs` (ВСЕ id) + `ollama` (:1234, только id с манифестом)
                |                      <- сюда смотрит «голый» `pi` из cmd без PI_CODING_AGENT_DIR
                |
                v
cmd/serve-llm.cmd              пересобирает реестр и стартует роутер на :8080
```

Почему роутер, а не N серверов на N портах: на карте 8 ГБ живёт ровно одна модель. Два
процесса дрались бы за VRAM, а так llama.cpp сам выгружает прошлую модель перед
загрузкой новой, и у pi остаётся один `baseUrl` — переключение это `/model`, а не
правка конфигов.

## Что попадает в список

Сканируются:

- `models\*.gguf` и `models\llm\**\*.gguf` (репозиторий);
- `GS_LLM_MODELS_DIR` (`;`-разделитель для второго диска) - задаётся в
  `local.env.cmd`, которого в git нет. Пусто по умолчанию: на чистом клоне
  чат-модель одна, из `models.manifest.json`.

Отбрасываются:

- `models\vlm`, `models\image`, `models\text_image_3D` — это модели ДРУГИХ серверов
  (Qwen2.5-VL на :8082, текстовый энкодер z-image-turbo, ComfyUI);
- `mmproj`, `bge-*`, `rerank`, `embed`, `clip` в имени;
- файлы без chat template (`--jinja` на них падает);
- дубликаты — по точному размеру в байтах (один и тот же GGUF лежит в двух местах).

## Контекст считается, а не угадывается

`gguf_meta.describe()` достаёт из заголовка `block_count`,
`full_attention_interval`, `attention.head_count_kv`, `attention.key_length` и
`context_length`. Дальше:

```
KV на токен = 2 * kv_heads * key_len * слоёв_с_полным_attention * 1.06
ctx         = (бюджет_VRAM - размер_файла) / KV_на_токен
```

SSM-слои гибридного стека Qwen3.5 в счёт не идут (у них постоянное состояние), поэтому
KV платится только за слои внимания: у 2B (6 полных слоёв из 24, 2 KV-головы по 256) это
6.4 КиБ/токен, у 9B (8 из 33) - 17 КиБ, а не 73, как у плотной модели того же размера.
Бюджет — `GS_LLM_VRAM_MB`, по умолчанию 7000 МБ из 8192. Потолок — `GS_LLM_CTX`
(по умолчанию 65536).

Проверка на живых числах: `qwen3.5-2b` (по умолчанию) = 1919 МБ весов Q8_0 + 407 МБ KV
при 64K = 2.3 ГиБ, `nvidia-smi` после загрузки показывает **3005 МиБ**. Для сравнения
`qwen3.5-4b` = 2614 МБ + 1088 МБ KV = 3.6 ГиБ (4600 МиБ на `nvidia-smi`), а `qwen3.5-9b`
= 5884 МБ + 1088 МБ KV = 6.4 ГиБ (~7.1 ГБ с буферами и рабочим столом). Сходится. Замер
той же сессией: 2B выдаёт ~120 ток/с, 4B ~87 - меньшая модель ещё и в 1.4 раза быстрее.

## Команды

```bat
cmd\models.cmd                 что зарегистрировано + что сейчас в VRAM
cmd\models.cmd --refresh       пересканировать и перезаписать ini + models.json
cmd\models.cmd --live          только ответ роутера
cmd\models.cmd --list          только реестр (работает при выключенном сервере)
```

`--refresh` нужен после копирования нового `.gguf`. Порядок: `--refresh`, затем
перезапуск окна LLM (`serve-all.cmd --restart`), затем перезапуск pi (он читает
`models.json` при старте).

## Переключение модели

Внутри pi: `/model` → выбрать id. Ctrl+P листает по кругу, если задан `--models`.

```bat
pi --model omnicoder-2-9b             :: сразу с нужной
pi --models qwen3.5-2b,ornith-1.5-9b-uncensored   :: ограничить круг переключения
```

Профиль (`pi-home-three` / `-godot` / `-unity`) при этом не меняется: RAG, скиллы,
MCP и SYSTEM.md те же — меняются только веса. Первый запрос к ещё не загруженной
модели ждёт загрузки с диска (9B ≈ 30–70 с, 4B примерно вдвое быстрее, 2B - быстрее
обоих), дальше она резидентна в VRAM.

## Дообучение

Модель можно дообучить под работу с четырьмя движками - но учат не API (он живёт в RAG и
прибит к версии), а **маршрутизации**: звать `*_rag_search` нужного движка, брать ассеты
своей связкой, не залипать на шаге. Полная инструкция - [`models/FINETUNE.md`](../models/FINETUNE.md),
готовый конфиг - [`models/finetune-2b.yaml`](../models/finetune-2b.yaml).

Что важно знать до старта:

- **8 ГБ не хватает на 4B в 16 бит** (~10 ГБ по замерам Unsloth). Поэтому и в работе, и в
  обучении локально стоит **2B**, а 4B - это шаг вверх на бесплатном Colab/Kaggle с тем же
  датасетом.
- **`flash_attn` на этой карте нет** (`sm75`, нужен `sm80`), вместо него `xformers`;
  SSM-слоям Qwen3.5 нужны `causal_conv1d` и `mamba_ssm` - их ставит
  `unsloth install-kernels`.
- **Новая модель подключается без правки кода**: положить `.gguf` под `models/`,
  затем `gs models --refresh`, затем `serve-all.cmd`.
- **Системный промпт при обучении и при работе должен совпадать.** Это первая причина
  «дообучил, стало хуже».

## Подводные камни

- **`--models-max` больше 1 на 8 ГБ не ставить.** Два 9B не влезут, и вместо ошибки
  будет тихий своп в системную память.
- **`GS_LLM_CTX` сменил смысл**: раньше это был `-c` единственной модели, теперь это
  потолок контекста при генерации реестра. Экспортированный `GS_LLM_CTX=32768`
  ужмёт все модели до 32K.
- **Ключи в INI = имена флагов без дефисов**, и неизвестный ключ роутер отвергает
  целиком (не игнорирует). Поэтому в preset пишется только проверенный минимум.
- **Мелкие модели (0.5B/0.8B) в списке есть, но агентом не работают** — они не
  держат формат tool-call. Это стенд для проверки «сколько тянет модель», не рабочий
  вариант. 2B - самая маленькая, которая формат держит, поэтому она и по умолчанию.
- **2B собран в Q8_0, а не в Q4_K_M.** Маленькие модели теряют на квантизации
  пропорционально больше крупных, а Q8_0 весит 1919 МБ - всё равно меньше, чем 4B в
  Q4_K_M (2614 МБ). Менять квант - значит править `models.manifest.json` и `gs models
  fetch`, а не только `match` в overrides.
- **4B не удалён, он остался в реестре** как переключаемая альтернатива (`/model
  qwen3.5-4b`) и как цель для обучения на Colab. Удалять его из `models/` не нужно:
  реестр держит любое число сборок, резидентна всё равно одна.
- `tools/compare_models.py` остался отдельным инструментом: он сам поднимает и гасит
  сервер под каждый кандидат и отказывается работать, если `:8080` уже занят.
