# Модели: реестр, роутер, переключение в pi

Одна модель на все движки больше не нужна. `:8080` теперь держит **llama.cpp router
mode** (build b11435): один процесс, INI-реестр, все id в `/v1/models`, загрузка по
первому запросу, вытеснение LRU при `--models-max`.

## Как это устроено

```
models/llm-overrides.json      ручные правки (единственный файл, который стоит править)
        |
        v
tools/llm_models.py            сканирует GGUF, читает метаданные, считает контекст
        |                      (tools/gguf_meta.py - разбор заголовка GGUF без зависимостей)
        +--> models/llm-preset.ini      реестр роутера: [id] + model + ctx-size + сэмплинг
        +--> models/llm-registry.json   те же факты для doctor/бенчмарка/чтения глазами
        +--> pi-home*/models.json       провайдер `3gs`, ВСЕ id (pi-home, -three, -godot, -unity)
                |
                v
cmd/serve-llm.cmd              пересобирает реестр и стартует роутер на :8080
```

Почему роутер, а не N серверов на N портах: на карте 8 ГБ живёт ровно один 9B. Два
процесса дрались бы за VRAM, а так llama.cpp сам выгружает прошлую модель перед
загрузкой новой, и у pi остаётся один `baseUrl` — переключение это `/model`, а не
правка конфигов.

## Что попадает в список

Сканируются:

- `models\*.gguf` и `models\llm\**\*.gguf` (репозиторий);
- `GS_LLM_MODELS_DIR` (по умолчанию `E:\Programs\LocalLLM\Models`, `;`-разделитель
  для второго диска) — задаётся в `cmd\_env.cmd`.

Отбрасываются:

- `models\vlm`, `models\image`, `models\text_image_3D` — это модели ДРУГИХ серверов
  (Qwen2.5-VL на :8082, текстовый энкодер z-image-turbo, ComfyUI);
- `mmproj`, `bge-*`, `rerank`, `embed`, `clip` в имени;
- файлы без chat template (`--jinja` на них падает);
- дубликаты — по точному размеру в байтах (один и тот же GGUF лежит в двух местах).

## Контекст считается, а не угадывается

`gguf_meta.describe()` достаёт из заголовка `block_count`,
`full_attention_interval`, `attention.head_count_kv`, `attention.key_length` и
`context_length`. Дальше:

```
KV на токен = 2 * kv_heads * key_len * слоёв_с_полным_attention * 1.06
ctx         = (бюджет_VRAM - размер_файла) / KV_на_токен
```

SSM-слои гибридного стека Qwen3.5 в счёт не идут (у них постоянное состояние), поэтому
у 9B выходит 17 КиБ/токен, а не 73. Бюджет — `GS_LLM_VRAM_MB`, по умолчанию 7000 МБ
из 8192. Потолок — `GS_LLM_CTX` (по умолчанию 65536).

Проверка на живых числах: `qwen3.5-9b` = 5884 МБ весов + 1088 МБ KV при 64K =
6.4 ГиБ, `nvidia-smi` после загрузки показывает ~7.1 ГБ с учётом буферов и рабочего
стола. Сходится.

## Команды

```bat
cmd\models.cmd                 что зарегистрировано + что сейчас в VRAM
cmd\models.cmd --refresh       пересканировать и перезаписать ini + models.json
cmd\models.cmd --live          только ответ роутера
cmd\models.cmd --list          только реестр (работает при выключенном сервере)
```

`--refresh` нужен после копирования нового `.gguf`. Порядок: `--refresh`, затем
перезапуск окна LLM (`serve-all.cmd --restart`), затем перезапуск pi (он читает
`models.json` при старте).

## Переключение модели

Внутри pi: `/model` → выбрать id. Ctrl+P листает по кругу, если задан `--models`.

```bat
pi --model omnicoder-9b              :: сразу с нужной
pi --models qwen3.5-9b,ornith-1.5-9b-crack   :: ограничить круг переключения
```

Профиль (`pi-home-three` / `-godot` / `-unity`) при этом не меняется: RAG, скиллы,
MCP и SYSTEM.md те же — меняются только веса. Первый запрос к ещё не загруженной
модели ждёт загрузки с диска (9B ≈ 30–70 с), дальше она резидентно в VRAM.

## Подводные камни

- **`--models-max` больше 1 на 8 ГБ не ставить.** Два 9B не влезут, и вместо ошибки
  будет тихий своп в системную память.
- **`GS_LLM_CTX` сменил смысл**: раньше это был `-c` единственной модели, теперь это
  потолок контекста при генерации реестра. Экспортированный `GS_LLM_CTX=32768`
  ужмёт все модели до 32K.
- **Ключи в INI = имена флагов без дефисов**, и неизвестный ключ роутер отвергает
  целиком (не игнорирует). Поэтому в preset пишется только проверенный минимум.
- **Мелкие модели (0.5B/0.8B) в списке есть, но агентом не работают** — они не
  держат формат tool-call. Это стенд для проверки «сколько тянет модель», не рабочий
  вариант.
- `tools/compare_models.py` остался отдельным инструментом: он сам поднимает и гасит
  сервер под каждый кандидат и отказывается работать, если `:8080` уже занят.
