# 3GS_Master

Локальная среда для трёх движков: **Three.js** (браузер), **Godot 4.7** и **Unity 6000.3**.  
Агент `pi` работает на локальной модели, с RAG по документации каждого движка, и генерирует  
ассеты на своём железе. Облако не нужно.

> Полное описание (архитектура, все лаунчеры, MCP, диагностика): **[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)**.  
> Правила агента: **[`AGENTS.md`](AGENTS.md)**. Ассеты: **[`ASSET-POLICY.md`](ASSET-POLICY.md)**.  
> Уровни (Three): **[`LEVEL-SCHEMA.md`](LEVEL-SCHEMA.md)**. Студия (Three): **[`STUDIO.md`](STUDIO.md)**.  
> Unity-стек отдельно: **[`unity/README.md`](unity/README.md)**, правила - **[`unity/AGENTS.md`](unity/AGENTS.md)**.

## Быстрый старт

Из корня репозитория (`cmd.exe` не ищет программы в текущей папке):

```cmd
cd /d F:\Pets\Projects\local_tools\3GS_Master
dev.cmd test
```

`dev.cmd <игра>` поднимает модели, проверяет окружение и открывает агента в папке игры.  
Флаг `--studio` добавляет студию (только для Three) в отдельном окне.

Та же точка входа через фасад: `gs.cmd help`.

## С нуля: создать проект

Проект - это папка `projects\games\<имя>`. Движок задаёт файл `engine.json` в её корне.  
**Лаунчеры его не создают**, поэтому для Godot и Unity его надо положить вручную. Без него  
агент работает в режиме Three.js.

### Three.js

```cmd
dev.cmd my_game
```

Папка создаётся пустой, и это нормально: файлы пишет агент. Если нужен стандартный скелет  
(сцена, студия уровней, линтер), его ставит отдельная команда:

```cmd
cmd\newgame.cmd my_game
```

По желанию положите явный маркер `projects\games\my_game\engine.json`:

```json
{ "engine": "threejs", "version": "r186" }
```

### Godot 4.7

1. Создайте проект в Godot (`Project Manager` -> `New Project`) в папке  
   `projects\games\<имя>`.
2. Положите рядом `engine.json`:

```json
{ "engine": "godot", "version": "4.7.2" }
```

1. Запустите:

```cmd
dev.cmd my_godot_game
```

Инструменты Godot (`godot_*`) появляются у агента только при `"engine": "godot"`. Если их  
нет в списке инструментов, значит вы не в Godot-проекте.

### Unity 6000.3

1. Создайте проект в Unity Hub (`New project`) в папке `projects\games\<имя>`.  
   Либо дайте это агенту: инструмент `unity_project_create` создаёт проект из ничего  
   (`Unity.exe -batchmode -createProject`) - руками скелет Unity не собрать.
2. Положите рядом `engine.json`:

```json
{ "engine": "unity", "version": "6000.3" }
```

1. Запустите:

```cmd
dev.cmd my_unity_game
```

Инструменты Unity (`unity_*`) появляются у агента только при `"engine": "unity"`.  
Проверить проект без агента: `gs unity-check my_unity_game` (линт Unity 5/6 API,  
`--compile` добавляет реальную компиляцию редактором).

Подробности стека (корпус, инструменты, лимиты) - в **[`unity/README.md`](unity/README.md)**.

## Как агент понимает, с чем работать

Решение принимается по трём признакам, а не по тексту задачи:

| Признак                   | Где                                | Что даёт                                        |
| ------------------------- | ---------------------------------- | ----------------------------------------------- |
| `engine.json` в проекте   | `projects\games\<имя>\engine.json` | движок: `threejs`, `godot` или `unity`          |
| `data\active_project.txt` | пишет `dev.cmd <имя>`              | какой проект активен                            |
| расширение `engine-gate`  | `.pi\extensions\engine-gate.ts`    | регистрирует инструменты движка только под него |

При старте агент показывает строку `Active project: ... (engine: <X>)`. По `<X>` выбирается  
и набор инструментов, и профиль агента (`pi-home-three` / `pi-home-godot` / `pi-home-unity` -  
у каждого свой `SYSTEM.md`, скиллы и `mcp.json`). `.pi\SYSTEM.md` запрещает смешивать движки  
в одном ответе: Three-API в Godot-проекте и наоборот. Если `engine.json` непонятен, агент  
останавливается и спрашивает.

## Как агент решает, что генерировать и чем

Правило: **арт делается своей локальной связкой в первую очередь** (см. `ASSET-POLICY.md`).  
Облачные генераторы (`ImageGen`, `VideoGen`, hosted API) не используются.

| Что нужно                           | Чем делается                             | Кто запускает              |
| ----------------------------------- | ---------------------------------------- | -------------------------- |
| Фон, спрайт, проп, сцена            | z-image-turbo (`sd-server` :8687), ~20 с | агент, инструмент `assets` |
| Надпись на картинке, лого, заставка | ComfyUI Qwen-Image 2.1, ~12 мин          | агент, `assets`            |
| Перекраска с сохранением формы      | ComfyUI `color_swap`                     | агент, `assets`            |
| Вырезание фона                      | BiRefNet, 24 с                           | агент, `assets`            |
| Увеличение картинки                 | Real-ESRGAN, 2x за ~14 с                 | агент, `assets`            |
| 3D-модель с UV и PBR                | Pixal3D / TRELLIS.2, ~18 мин             | агент, `assets`            |
| Риг, анимация, ретопо, GLB↔FBX      | Blender 5.2 (`blender --background`)     | агент (DCC-шаг поверх GLB) |
| Тайлы, звук, шрифты                 | скачивается, с записью лицензии          | агент (второй эшелон)      |

Выбор движка агент делает по таблице: по умолчанию z-image, надпись - Qwen-Image,  
перекраска - `color_swap`. Ключевой персонаж или главный арт идут через локальную генерацию,  
даже если пользователь не просил «сгенерируй».

**Blender - DCC-шаг, которого у связки не было.** ComfyUI отдаёт сырой GLB и на этом  
останавливается; всё, что требует *редактирования* меша - авто-риггинг и ретаргет анимации,  
quad-ретопология и чистка UV, конвертация GLB↔FBX↔OBJ, перебейк текстур, headless-превью -  
идёт через Blender в фоне. Путь берётся из `BLENDER_EXE` (`cmd\_env.cmd`, на этой машине  
`E:\Programs\Blender\blender.exe`), переопределяется `THREE_BLENDER_EXE` / `GDM_BLENDER_EXE` /  
`UNIM_BLENDER_EXE`. Наличие проверяет `cmd\doctor.cmd`.

**GPU.** На 8 ГБ VRAM одновременно живёт одна модель: llama-server (:8080), sd-server  
(:8687) или ComfyUI (:8188). Real-ESRGAN и Blender - исключения. Агент сам модели не  
поднимает: серверы запускаете вы (`dev.cmd` или `serve-all.cmd`).

**Поиск - гибридный, и его уточняет реранкер.** `:8081` считает эмбеддинги (dense),  
SQLite FTS5/BM25 - лексику, RRF складывает оба ранга. Отдельный кросс-энкодер  
`bge-reranker-v2-m3` на `:8083` (`gs rerank`) проходит вторым проходом по верхушке  
списка и читает запрос с пассажем *вместе* - на корпусе Unity он поднял настоящий ответ  
с 46-го места на 5-е. Он **опционален**: без него поиск работает на гибридной паре и  
считает сбои в `rerank_failures`. Порт `:8082` занят сервером зрения Qwen2.5-VL.

**Godot - тот же принцип.** Генерация локальная, теми же инструментами, что и у Three  
(`asset_image`, `asset_edit`, `asset_remove_bg`, `asset_to_3d`, `asset_character`, `asset_generate_pack`).  
Результат кладётся в `<проект Godot>\assets\`, а не в `public\assets\`. Таблица выше  
применяется и к Godot.

**Unity - тот же принцип, но каталог внутри `Assets/`.** Результат кладётся в  
`<проект Unity>\Assets\Generated\` - именно внутри `Assets/`, иначе Unity файл не импортирует  
и он не появится ни в Project-окне, ни в билде. `.glb` Unity импортирует только при  
установленном `com.unity.cloud.gltfast`.

**Порядок для любого движка:**

1. **Первый эшелон - локальная генерация.** Всегда, без интернета.
2. **Второй эшелон - бесплатные ассеты из сети** (`asset_search`, `asset_license`,  
   `asset_download`, `asset_install`). Только если локальной генерации не хватает И есть доступ  
   в интернет. Каждая загрузка пишет лицензию. Включается флагом `GDM_ENABLE_ASSET_TOOLS=1`  
   и выключена по умолчанию.

## Каталоги

| Путь              | Что                                                                              |
| ----------------- | -------------------------------------------------------------------------------- |
| `projects\games\` | игры (данные пользователя)                                                       |
| `godot\`          | Godot-стек: `gdmaster`, RAG по Godot 4.7                                         |
| `unity\`          | Unity-стек: `unimaster`, RAG по Unity 6000.3                                     |
| `vendor\three\`   | рантайм three.js r186, одна копия на репозиторий                                 |
| `stack\`          | канонический скелет игры Three (`newgame.cmd`)                                   |
| `studio\`         | оболочка студии уровней, одна на все игры                                        |
| `threejs\`        | RAG и пайплайн ассетов (Python)                                                  |
| `tools\`          | утилиты: линтеры, проверки, студия                                               |
| `cmd\`            | служебные лаунчеры                                                               |
| `tests\`          | тесты (`cmd\test.cmd`)                                                           |
| `knowledge\`      | корпус документации Three.js для RAG                                             |
| `models\`         | веса LLM/embed/rerank; внутри `text_image_3D\` - портативный ComfyUI, не удалять |
| `bin\`            | бинарники, не править                                                            |
| `.venv\`          | один Python на все три стека (RAG, ассеты, линты)                                |

## Что в репозитории, а что нет

В git лежит код, корпус документации и конфигурация агента - около 37 МБ. Всё тяжёлое
и воспроизводимое исключено через `.gitignore`:

| Исключено | Почему |
| --- | --- |
| `models\`, `bin\` | веса моделей и бинарники движков - десятки гигабайт, качаются по README |
| `godot\data\`, `unity\data\`, `unity\knowledge\` | кэши и корпуса, собираются скриптами стека |
| `data\sqlite\`, `data\gen-staging\` | индекс RAG и промежуточные артефакты генерации |
| `projects\`, `logs\` | пользовательские игры и логи сессий |
| `pi-home*\sessions\`, `pi-home*\auth.json` | история сессий и креды агента |

Поэтому клон без дополнительных шагов не запустится: сначала нужны модели и `.venv`,
порядок - в «Быстром старте» выше.
